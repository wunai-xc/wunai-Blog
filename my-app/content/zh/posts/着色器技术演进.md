## 引言

在计算机图形学的硬件加速史上，着色器（Shader）的出现标志着GPU从专用图形管道蜕变为通用可编程处理器的关键转折。着色器本质上是一段运行在GPU上的用户自定义程序，用于控制顶点变换、光照计算、纹理采样、几何生成乃至通用并行计算。在硬件层面，这些程序被组织为多个阶段，每个阶段负责图形渲染管线中的特定环节。而在软件层面，开发者通过高级着色器语言（如HLSL、GLSL、Cg）编写代码，经由编译器转换为GPU可执行的机器码。理解着色器技术的发展，需要同时把握三条脉络：**硬件可编程能力的演进**、**API着色器模型的迭代**，以及**着色器中间表示语言的标准化**。

## 第一章 前着色器时代：固定功能管线（1992—2000）

在着色器概念出现之前，GPU的图形管线是固定功能的。开发者只能通过调整状态参数（如光照类型、纹理混合模式）来间接控制渲染结果，无法编写自定义的逐顶点或逐像素程序。

**1992年**，Silicon Graphics发布了**OpenGL 1.0**规范，由OpenGL架构评审委员会（ARB）管理，成为跨平台图形API的事实标准。**1995年**，微软发布**Direct3D**，作为DirectX的图形组件进入Windows生态。二者的固定管线都包含以下阶段：顶点变换、图元装配、光栅化、纹理映射和混合。光照计算仅限于内置的Phong或Blinn-Phong模型，纹理操作为静态的多重纹理混合。

**1998年至2000年**，NVIDIA的**Riva 128**和**Riva TNT**开始支持多重纹理，**GeForce 256**（1999年）首次将硬件T&L（Transform and Lighting）集成到GPU中，将顶点变换从CPU卸载到GPU。但此时的管线仍然是不可编程的——开发者只能通过`TextureStageState`等状态接口调整固定功能的行为。

## 第二章 可编程着色器的诞生（2001—2002）

### 2.1 DirectX 8.0 与 Shader Model 1.0

**2001年初**，NVIDIA的**GeForce 3**成为第一个支持可编程顶点着色器的GPU。同年，微软在**DirectX 8.0**中正式提出了**Shader Model**的概念，将着色器按操作对象分为**顶点着色器**（Vertex Shader）和**像素着色器**（Pixel Shader）。

**Shader Model 1.0/1.1**的能力极为有限：

- **顶点着色器**：最多128条浮点指令，支持静态分支
- **像素着色器**：最多16条定点向量指令，支持4个纹理，1级依赖纹理
- **不支持动态流控制**（循环和条件分支必须在编译时展开）

同一时期，OpenGL通过**GL_ARB_vertex_program**和**GL_ARB_fragment_program**扩展提供了等效的汇编级着色器支持，**OpenGL 1.4**（2002年）集成了这些扩展。

![NVIDIA GeForce 3像素着色器效果演示](/images/shader/geforce3-pixel-shader.jpg)

### 2.2 高级着色器语言的诞生：HLSL 与 Cg

在汇编语言中编写着色器极为困难。**2002年12月**，微软在**DirectX 9.0**中首次公开发布了**HLSL**（High Level Shader Language），一种基于C语言的高级着色器语言。

几乎同时，NVIDIA与微软合作推出了**Cg**（C for Graphics），由NVIDIA于**2002年6月**正式发布。Cg的语法基于C语言，支持可编程顶点和像素着色器开发，并提供硬件无关的编程接口。Cg与HLSL共享了大量语法和编译器基础设施，NVIDIA的Cg编译器同时针对DirectX和OpenGL进行优化。

Cg的引入使得开发者可以用类似C的语法编写着色器，由编译器生成GPU机器码，极大地降低了GPU编程的门槛。

## 第三章 Shader Model 2.0 与 GLSL 的引入（2002—2004）

### 3.1 DirectX 9.0 与 Shader Model 2.0

**2002年12月**，DirectX 9.0的发布带来了**Shader Model 2.0**，被业界视为一次“真正的技术革命”。

SM 2.0的核心进步：

- **浮点精度**：顶点和像素着色器均支持完整的32位浮点运算（SM 1.x的像素着色器为定点）
- **指令数量**：像素着色器指令上限提升至64条
- **动态流控制**：像素着色器支持有限的动态分支
- **可编程依赖纹理**：像素着色器可以基于计算结果动态采样纹理

这些能力使开发者能够在GPU上实现水面光影、雾化等此前无法实现的实时特效。

### 3.2 OpenGL 2.0 与 GLSL 的正式引入

**2003年7月**，OpenGL 1.5发布，通过ARB扩展提供了OpenGL着色语言（GLSL）的初步规范。**2004年9月**，**OpenGL 2.0**正式发布，GLSL作为核心规范被纳入其中。

**GLSL**的语法同样基于C语言，但与HLSL和Cg的设计哲学有所不同。GLSL更强调跨平台一致性，其变量类型（如`vec4`、`mat4`）和内置函数（如`texture2D`、`normalize`）直接映射到GPU硬件能力。GLSL的初始版本为**1.10**，随OpenGL 2.0发布。

### 3.3 Shader Model 3.0

**2004年7月**，DirectX 9.0c发布，引入了**Shader Model 3.0**。SM 3.0的指令数量实现了质的飞跃：顶点和像素着色器的指令上限均从SM 2.0的256条和96条扩展至**65,535条**，并支持完整的动态分支和子程序调用。32位浮点运算成为强制性要求，光照计算精度进一步提升。

NVIDIA的**GeForce 6系列**是首批完整支持SM 3.0的GPU。《Far Cry》1.2补丁是首个利用SM 3.0的游戏，将着色器指令数的大幅提升用于性能调优和更复杂的光照计算。

## 第四章 统一着色器架构与几何着色器的诞生（2006—2007）

### 4.1 DirectX 10 与 Shader Model 4.0

**2006年**，微软随Windows Vista发布**DirectX 10**，引入了**Shader Model 4.0**。这是GPU架构的一次分水岭。

SM 4.0的核心变革：

- **统一着色器架构**：顶点着色器和像素着色器的硬件规格被统一，两者共享相同的指令集和寄存器资源，GPU内部不再区分专用硬件单元。这意味着GPU的流处理器可以灵活调度为顶点处理或像素处理，大幅提升了硬件利用率。
- **几何着色器**（Geometry Shader） ：在VS和PS之间引入了一个全新的可编程阶段，可以批量处理图元（点、线、三角形），支持图元生成和销毁。
- **指令数量**：从512条跃升至**64,000条**
- **临时寄存器**：从32个增至**4,096个**
- **纹理操作**：从16个增至**128个**
- **纹理分辨率**：从2048×2048提升至**8192×8192**
- **HDR原生支持**：材质纹理格式变为硬件支持的RGBE格式，简化了HDR渲染流程

几何着色器虽然功能强大，但因性能限制在实际游戏中应用有限。DirectX 11后来引入了Tessellation技术来替代其部分功能。

### 4.2 OpenGL 3.0 与 GLSL 1.30

**2008年8月**，OpenGL 3.0发布，GLSL升级至**1.30**。这一版本引入了`in`/`out`关键字替代`varying`和`attribute`，并增加了纹理数组和整数纹理等特性。

## 第五章 通用计算与 Tessellation（2009—2010）

### 5.1 DirectX 11 与 Shader Model 5.0

**2009年10月22日**，微软随Windows 7发布**DirectX 11**，引入**Shader Model 5.0**。

SM 5.0的核心新增：

- **计算着色器**（Compute Shader） ：这是SM 5.0最具革命性的特性。计算着色器使GPU能够直接执行通用并行计算任务，而不再局限于图形渲染。例如高清视频转码、物理模拟和机器学习推理都可以在GPU上高效运行。DirectCompute API的引入进一步推动了GPGPU（GPU通用计算）的发展。
- **Tessellation**：引入外壳着色器（Hull Shader）和域着色器（Domain Shader），使GPU能够在硬件层面进行几何细分，动态生成更精细的曲面。
- **完整的着色器阶段**：VS、HS、DS、GS、PS、CS六种着色器类型全部可用。

### 5.2 OpenGL 4.0 与 GLSL 4.00

**2010年3月**，Khronos Group同时发布**OpenGL 3.3**和**OpenGL 4.0**，GLSL分别升级至3.30和4.00。

OpenGL 4.0与DirectX 11的SM 5.0能力对标，新增了两个Tessellation着色器阶段（Tessellation Control Shader和Tessellation Evaluation Shader），支持64位双精度浮点着色器运算，并引入着色器子程序（Shader Subroutines）以增强编程灵活性。

## 第六章 低开销API的崛起：Mantle、Vulkan 与 DirectX 12（2013—2016）

### 6.1 AMD Mantle

**2013年9月**，AMD发布了**Mantle**——一个低开销、接近硬件的图形API。Mantle的着色器设计有一个关键特点：**HLSL兼容性**。Mantle使用与DirectX相同的HLSL前端编译器，并通过开源组件将DirectX着色器翻译为Mantle接受的中间语言（基于AMD IL的子集）。

Mantle还首次引入了**异步着色器**技术，允许图形和计算任务通过多队列并行执行。虽然Mantle本身因AMD的战略调整而被Vulkan取代，但其设计理念深刻影响了后续所有低开销API。

### 6.2 Vulkan 与 SPIR-V

**2016年2月**，Khronos Group发布**Vulkan 1.0**。Vulkan的核心变革在于着色器的编译模型：它**要求着色器以SPIR-V二进制格式提供**，而非像OpenGL那样直接传递GLSL源代码字符串。

**SPIR-V**（Standard Portable Intermediate Representation）是一种为图形着色器阶段和计算内核设计的二进制中间表示。开发者仍然可以用GLSL或HLSL编写着色器，但需要通过编译器（如glslangValidator或glslc）将其编译为SPIR-V二进制，再通过`vkCreateShaderModule`加载。

SPIR-V的核心优势：

- **分离编译链**：高级语言前端和GPU驱动后端解耦，驱动不再需要内置完整的GLSL编译器
- **预编译**：着色器可以在应用构建阶段（AOT）完成编译，运行时加载二进制，消除运行时的编译开销
- **多语言支持**：GLSL、HLSL、ESSL均可编译为SPIR-V，为跨平台开发提供了统一的目标格式

### 6.3 DirectX 12 与 Shader Model 6.0

**2015年7月**，微软随Windows 10发布**DirectX 12**，引入**Shader Model 6.0**。SM 6.0在DX12中新增了**波形内部函数**（Wave Intrinsics），支持SIMD级别的并行运算，并引入了几何着色器实例化技术。

## 第七章 Shader Model 6.x 系列的持续演进（2018—2026）

DirectX 12之后的Shader Model迭代进入了快速演进期。

**SM 6.5**（2022年）引入了**光线追踪着色器**的增强支持，包括光线生成着色器、最近命中着色器和未命中着色器的更灵活组合。

**SM 6.9**（2026年2月）是近年最重要的更新之一：

- **长向量**：打破HLSL中向量最多4个分量的长期限制，支持最多**1024个元素的向量**，使着色器可以直接处理大规模数据，无需手动打包
- **16位和64位着色器**与波操作被设为**强制性要求**
- **着色器执行重排序**（SER）成为SM 6.9的必需特性，在路径追踪中可实现最高**2.3倍**的性能提升

**SM 6.10**（2026年4月）带来了三大新特性：

- **LinAlg矩阵API**（`linalg::Matrix`） ：使GPU直接运行矩阵运算，服务于机器学习驱动的图形工作负载，如缩放、降噪和神经渲染
- **Group Wave Index**：帮助着色器在不同显卡架构下安全识别波阵工作组
- **可变工作组共享内存**：将共享内存上限从**32KB**（网格着色器为28KB）扩展至硬件支持的上限，并新增运行时查询接口以获取实际硬件限制

硬件支持方面，AMD的RX 7000/9000系列、Intel的锐炫B系列、NVIDIA的RTX系列均已支持SM 6.10的大部分特性，其中LinAlg矩阵API仅限AMD RX 9000系列。

## 总结

着色器技术的演进反映了GPU从固定功能图形加速器向通用并行处理器的根本性转变。这一历程可概括为四个阶段：

**第一阶段（2001—2004）** ：从固定管线到可编程着色器，SM 1.0至3.0逐步扩展了指令数、浮点精度和流控制能力，HLSL、Cg、GLSL三种高级着色器语言的诞生使GPU编程走向大众化。

**第二阶段（2006—2010）** ：统一着色器架构消除了顶点和像素处理器的硬件壁垒，几何着色器和计算着色器的引入使GPU超越了纯图形渲染的范畴。

**第三阶段（2013—2016）** ：Mantle、Vulkan和DirectX 12推动了低开销API革命，SPIR-V作为二进制中间表示重塑了着色器的编译和分发模型。

**第四阶段（2018—2026）** ：Shader Model 6.x系列持续引入面向机器学习、神经渲染和硬件直接访问的新特性，LinAlg矩阵API和长向量支持标志着着色器正在进入与AI工作负载深度融合的新时代。

从汇编级的手工编码到C-like高级语言，从固定4分量向量到1024元素长向量，从源码字符串到二进制中间表示——着色器的抽象层次不断提高，可编程能力持续扩展，而底层的物理原理始终未变：**用最小的晶体管代价，换取最大的计算表达力**。
