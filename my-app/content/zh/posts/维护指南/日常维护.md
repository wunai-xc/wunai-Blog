## 一、通用原则（先看这四条）

1. **改之前先 `git pull`。** 手机上用 Spck 或 Termux 手动改过文件的话，两个副本会分叉，不先同步就会推送失败。
2. **一次改动一个主题**，提交信息用中文，说清「改了什么、为什么」。
3. **改完必须推送**，并在 CI 跑完后确认线上生效（见下篇）。
4. **动代码之前先问自己：这条约定以前定过吗？** 全站直角、亚克力材质、`--header-h` 定位、图标白名单等都不是随手写的，破坏它们会连带一片地方出问题。约定清单在《博客书写规范》的 3.2 节。

## 二、改文章内容

### 新建一篇文章

在 `content/zh/posts/` 下新建 `.md`（或 `content/en/posts/`），frontmatter 最少写 `title` 与 `date`：

```yaml
---
title: "文章标题"
date: 2026-09-19
draft: false
tags: ["标签"]
categories: ["分类"]
summary: "一句话摘要"
---
```

正文**从 `##` 开始**，不要再写 `# 标题`（`title` 已经是 H1）。

写完把 `draft` 设为 `false`（或删掉该行）才会发布。字段全表见《博客书写规范》5.1。

### 改一篇已有文章

直接改文件即可。**URL 由文件名决定**，不改文件名就不会变动、外链不会失效。

⚠️ **改文件名等于改 URL**，原地址会 404。真要改，就在 `public/_redirects` 里补一条 301（写法见该文件内的注释）。

### 删除一篇文章

删掉文件即可。**注意**：如果它被别的文章用相对 `.md` 链接引用过，那些链接会变成死链；被 `tags` / `categories` 引用不影响。

### 长文拆成「卡组」

多篇文章归一组时用卡组（文章列表页会折叠成一张叠层卡片）：

```
content/zh/posts/我的专题/
├── _index.md      # 组说明：title / description / cover
├── 第一篇.md      # order: 1
└── 第二篇.md      # order: 2
```

组内顺序用 frontmatter 的 `order` 控制（不写则按文件名数字前缀，再否则按文件名）。
完整规则见《博客书写规范》5.4。

**本文所在的《博客维护指南》与《博客书写规范》本身就是卡组实例，可直接对照。**

## 三、加 / 改友链

只改 `my-app/lib/links.ts` 里的 `FRIEND_LINKS` 数组：

```ts
{
  name: "对方名称",
  url: "https://对方站点/",              // 指「对方的博客」，不是 GitHub 主页
  avatar: "https://github.com/<用户名>.png?size=96",
  description: { zh: "中文简介", en: "English intro" },
}
```

三条经验：

- **头像优先用 GitHub 官方端点** `github.com/<用户名>.png?size=96`（会 302 到 `avatars.githubusercontent.com`）。比外链图床稳，不会被防盗链拦，`size=96` 够 48px 卡片两倍图用。
- **简介要取自对方站点自己的原话**，不要自己编。抓一下对方首页，通常有现成的一句。没有就留空，卡片会自动回退显示域名。
- 特殊情况的写法可参考现有条目：`subear` 用对方站内头像图、`GTMC` 用 favicon、`并非懒得喷` 的中英都保留中文原句（一句诗不宜机器翻译）。

### 友链的「准入门槛」是对方的，不是你的

有些站（如戈登的站）在友链页写明要求：不接受 `github.io`、`vercel.app` 等第三方域名、需先互动等。**这是对方的规则**，加之前扫一眼对方友链页，能省掉一次白申请。

## 四、改站点信息与联系方式

**站点级常量全在 `my-app/lib/site.ts`**：

| 想改什么 | 改哪里 |
|---|---|
| 站点标题、作者、站点 URL | `SITE.title` / `SITE.author` / `SITE.url` |
| 首页首屏问候语与简介 | `homeInfo.zh` / `homeInfo.en` |
| 顶栏与各处的界面文案 | `i18n.zh` / `i18n.en`（**中英各一份，别只改一边**） |
| 页脚联系方式（邮箱/GitHub/仓库/社交账号） | `contact` |
| 页脚欢迎语、仓库名等**文案** | `i18n` 里的 `contactLabel` / `contactBody` / `repoLabel` |

⚠️ **地址与文案是分开存的。** `contact` 里只放与语言无关的地址和账号，凡是「要翻译的文字」都在 `i18n`。
曾经把 `label` / `body` / `repoLabel` 写在 `contact` 里，结果英文页也显示中文。

⚠️ **改 `SITE.url` 后**，`rss.xml` 与 `sitemap.xml` 是构建期生成的、会自动跟随；但**已经分发出去的旧链接不会变**。

## 五、加一个图标

图标是**本地打包的白名单**，不会请求外部图标服务（国内也能显示）。三步：

1. **先验证名字存在**，别凭印象写：打开 `https://api.iconify.design/mdi/<名字>.svg`，
   返回 SVG 就是有，404 就是没有。
2. 在 `my-app/lib/icons.ts` 里 `import` 该图标并登记进 `icons` 对象。
3. 组件里用 `icons["mdi:xxx"]` 引用。

⚠️ **MDI 没有 `bilibili` 图标**（已实测 404），页脚用 `television-classic` 代替。
⚠️ 名字写错会让**构建直接失败**（找不到文件），所以第 1 步不能省。

## 六、改样式

样式集中在 `my-app/app/globals.css`（单文件，约 2700 行，有分段注释）。

### 改颜色

改 `:root` 与 `html.dark` 里的**令牌**，不要在组件里写死色值：

```css
:root     { --accent: #2563eb; --bg: #fffbfb; --fg: #171717; ... }
html.dark { --accent: #60a5fa; ... }
```

预设配色方案在 `html[data-palette="..."]` 里，**必须与 `lib/settings.ts` 的 `PALETTES.swatch` 保持一致**。

### 改顶栏高度

只改一个变量 `--header-h`（`:root` 90px / 平板 78px / 手机 70px）。
首屏高度、锚点偏移都挂在它下面。

⚠️ **阅读区的浮动控件用的是 `--chrome-top`（初值 = `--header-h`），不是 `--header-h`。**
粘性标题 / 目录按钮 / 目录面板靠它定位，因为顶栏在阅读时会隐藏、那时它们要归零上移。
（曾经这三处写死 `56px` / `57px` / `96px`，而手机上顶栏是 70px ——
**顶栏比它们高，直接把粘性标题与目录按钮盖住了。**）

### 改角标（面板四角的十字线）

调 `:root` 里的 `--cn-color`（交点色，两个主题都跟随 `--accent`）、
`--cn-end`（终点色，亮色白 / 暗色取 `--bg`）、`--cn-w`（线宽，现为 `0.5px`）、
`--cn-inset`（内缩 5px）、`--cn-arm`（臂长 3.5px）。整体浓度改伪元素上的 `opacity`（0.6）。

### 改入场动画

全站共用 `slide-in-from-right` 一段关键帧，时长由 `--enter-duration` 控制（默认 500ms）。两条要记住的：

- **卡片动画的是卡片本体**（`.post-card` / `.collection-card` / `.home-card` / `.update-item`），
  内部文字不再单独动；错位延迟靠 `.post-card:nth-child(n)` 那组规则。
- **填充模式是 `backwards`，别改成 `both`**。`both` 会在动画结束后继续占着 `transform`，
  从而压过 hover 的位移（标签浮起、卡片鼠标跟随倾斜都会失效）。

### 改阅读时的顶栏行为

“滚过 120px 自动隐藏、双击滑出”的逻辑在 `components/ReadingHeader.tsx`，只挂在**文章页**。
阈值（`TOP_ZONE`）与双击间隔（`DOUBLE_TAP_MS`）是该文件顶部的常量。

### 三条不能破的既有约定

- **全站直角**：所有 `border-radius: 0`。参考稿带来的圆角不要照抄。
- **亚克力材质**走 `--reading-*` / `--card-acrylic-*` 令牌；暗色下**不要任何白色渐变**（sheen / glow 取全透明而不是 `none`，因为它们在逗号列表里）。
- **`backdrop-filter` 不能和 `transform` 加在同一元素上**（会被强制扁平化）；卡片因此把材质放在 `::after` 上。

## 七、加一个设置项

设置项是三处联动的，缺一不可：

1. `my-app/lib/settings.ts` — 选项定义、localStorage 键名、默认值
2. `my-app/components/SiteSettings.tsx` — 设置页 UI
3. `my-app/app/globals.css` — 用 `html[data-<键名>="<值>"]` 写样式分支
4. 外加 `my-app/app/layout.tsx` 里的**首屏内联脚本**：必须在那里读取并写到 `<html>` 上，否则刷新会闪一下

## 八、放图片

图片放 `public/` 下任意子目录，正文用**以 `/` 开头的绝对路径**：

```
public/images/我的专题/a.png   →   正文写 ![](/images/我的专题/a.png)
```

⚠️ **不要用相对路径**（`![](a.png)`）：渲染器会补成 `/<lang>/posts/<slug>/a.png`，
要求你在 `public/` 下手搭出和文章 URL 一样的目录层级，很容易搞错。除非有明确需求，一律用绝对路径。

**图片只能用网页上传**（GitHub 网页版的 Add file → Upload files）。
命令行工具无法安全搬运二进制文件，所以换图、加图都得走网页。

卡组的封面写在 `_index.md` 的 `cover.image`，会**填满卡片边框内部**。

## 九、什么时候该更新文档

改完之后，判断这三份文档是否需要同步更新：

| 文档 | 给谁看 | 什么时候必须改 |
|---|---|---|
| `README.md` | 仓库访客 | 特性、技术栈、部署方式有变 |
| 《博客书写规范》 | 作者与 AI | 约定、字段、结构、坑点有变 |
| 本文《博客维护指南》 | 作者本人 | 操作步骤有变（改了文件位置、改了流程） |

具体规则见下篇「五、文档同步规则」。
