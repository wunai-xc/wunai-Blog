## 一、一次改动的完整流程

```
① git pull                      先同步，避免分叉
② 改文件                        一次只做一个主题
③ 看情况更新文档                见「五、文档同步规则」
④ git add <具体路径> / commit    提交信息用中文说明改了什么、为什么
⑤ git push                      推送到 origin/main
⑥ 等 CI 跑完                    见下节；Cloudflare 侧约 1 分钟
⑦ 打开线上页面确认               CI 的绿勾不代表页面对，要亲眼看到
⑧ 确认工作区干净                git status
```

**第 ⑦ 步不能省。** 构建成功只说明「代码能编译」，不说明「效果符合预期」。
网页有缓存，看不到变化时先看下节「三、Service Worker 与缓存」。

## 二、两条部署管线

推送 `main` 后会触发两条独立的管线：

| 管线 | 位置 | 现状 |
|---|---|---|
| **Cloudflare Pages 的 Git 集成** | 仓库 Settings → 集成 | ✅ **真正在部署的那条**。根目录设为 `my-app`，自动构建并发布 |
| **GitHub Actions 工作流** | `.github/workflows/deploy.yml` | ⚠️ **已改为仅手动触发**（`workflow_dispatch`）。它最后一步 `wrangler pages deploy` 一直报失败却不影响发布，只是给出误导性红灯；且与上面那条重复，故关掉 |

**结论：正常推送不需要管 Actions。** 看部署状态以 Cloudflare 为准。
需要手动跑那条工作流时，在仓库 Actions 页面点 Run workflow。

### 构建是怎么跑的

Cloudflare 侧执行的命令是：

```
cd my-app && npm ci && npm run build
```

`npm run build` 前有 `prebuild` 钩子，会依次生成搜索索引、RSS、changelog：

```
node scripts/generate-search-index.mjs
node scripts/generate-rss.mjs
node scripts/generate-changelog.mjs
```

**顺序有意义**：后两个脚本读 `content/`、写 `public/`，必须在 `next build` 之前跑完，
否则打包不进产物。`generate-changelog.mjs` 优先走 GitHub API（CI 是浅克隆，`git log` 取不到 5 条），
失败时回退 `git log`，两个都失败则保留旧文件、**绝不令构建失败**。

## 三、Service Worker 与缓存

PWA 的 Service Worker（`my-app/public/sw.js`）会缓存静态资源。有两处坑：

### 坑 1：改了资源却不升版本 → 客户端一直用旧的

静态资源是 **cache-first**，而缓存名带着 `VERSION`。
**只要 `VERSION` 不变，旧文件永远不会被清掉**，于是出现「HTML 已更新、页内跑的 JS 还是旧的」，
症状是页面能打开但点链接跳转没反应。

→ **改了 `sw.js` 或任何静态资源策略，必须升 `VERSION`。**

### 坑 2：失败了也被缓存 → 永久显示不出来

早期版本会把**任何响应**（含 404）写进缓存，而 cache-first 从不校验。
典型踩法：先推了引用 `/ESKAPE/*.webp` 的文章、图片晚一小时才上传，
期间打开过那篇文章 → 6 张图的 404 被缓存 → 图片上线后仍然显示不出来。

已在 v5 修掉：**只缓存成功响应**，缓存里若命中非成功响应一律当未命中重新取。
另外注册 SW 时加了 `updateViaCache: 'none'`，强制不走 HTTP 缓存取 `sw.js` 本身。

**这说明：先推文章、后传图片是危险的顺序。图片和引用它的文章要在同一次推送里。**

### 看不到更新时的急救顺序

1. **无痕窗口**打开 —— 排除客户端缓存，最快的一招
2. 普通窗口：清站点数据（设置 → 隐私 → 删除浏览数据 → 缓存 + Cookie）
3. 仍不行：确认 CI 真的构建成功了（Cloudflare 面板），而不是只看了推送成功

## 四、构建失败的常见原因

| 现象 | 原因 | 改法 |
|---|---|---|
| `TS7053: Element implicitly has an 'any' type` | 用 `string` 索引了字面量键的 const 对象（如 `icons[...]`） | 把字段类型收窄为 `keyof typeof`，或给数据加类型标注 |
| `Cannot find module '@iconify/icons-mdi/xxx'` | 图标名字不存在 | 先用 `api.iconify.design/mdi/<名字>.svg` 验证，再登记 |
| `Page "/xxx/[y]" returned an empty array from generateStaticParams()` | `output: "export"` 要求每个动态路由至少产出一个页面 | 列表为空时返回一个占位参数，页面里查不到就走 `notFound()`（`lib/content.ts` 的 `EMPTY_PARAM` 就是这个用途） |
| `Module not found: Can't resolve 'fs'` | 客户端组件里用了 Node 专用模块 | 挪到服务端组件，或用 `fs` 的代码改读构建期产物 |
| 构建成功但页面空白 | 客户端组件里用了服务端才有的 API，或 `useEffect` 依赖写错 | 看浏览器控制台报错 |

**排查顺序：先看构建日志里那一行 `error` 的文件与行号，再看具体信息。**
Cloudflare 与 Actions 的日志都能点开看。

## 五、文档同步规则

**三份文档，每次推送前过一遍：**

| 文档 | 路径 | 读者 | 何时必须更新 |
|---|---|---|---|
| README | `README.md` | 仓库访客 | 特性、技术栈、目录结构、部署方式有变 |
| 博客书写规范 | `content/zh/posts/博客书写规范/` | 作者与 AI | 约定、字段、文件结构、坑点有变 |
| 博客维护指南 | `content/zh/posts/维护指南/` | 作者本人 | 操作步骤有变（文件位置、流程、命令） |

判定标准就一条：**「照着这份文档做，会不会做错？」会，就必须改。**

如果这次改动确实不需要更新任何一份，**在提交信息末尾显式写一行**：

```
文档：无需更新（仅改友链数据，三份文档都未描述具体友链）
```

这样做的目的是让「没更新」成为一个**显式决定**，而不是事后想不起来的遗漏。
三份文档互相引用，改动一处时记得检查交叉引用是否还成立。

## 六、症状 → 排查路径速查

| 症状 | 先查这里 |
|---|---|
| 页面改了但线上没变 | 无痕窗口试一次 → 清了缓存 → CI 是否真构建成功 |
| 点链接跳转卡在加载动画 | Service Worker 版本错配（升 `VERSION`） |
| 某张图显示不出来 | 无痕窗口 → 文件是否真在仓库里（`globals.css` 的 `.figure-missing` 占位块会显示 alt 文字）→ 大小写 → 外链是否被防盗链拦 |
| 整篇文章从搜索里消失 | `scripts/generate-search-index.mjs` 是否覆盖到它的目录（必须递归子目录） |
| 数学公式溢出卡片 | `.katex-display` 的 `display: block` 是否被覆盖；长公式自动缩放逻辑在 `PostBody.tsx` |
| 打印出来的表格被裁切 | 打印段是否把表格从 `display:block` 改回 `display:table` |
| 文章不在列表页显示 | `draft: true`？`hiddenInHomeList`？属于卡组？（卡组及组内文章**不上首页**，这是设计行为） |
| 上下篇顺序反了 | `getPrevNext`：卡组内按 `order` 升序，组外按日期降序，两者方向相反 |
| 友链卡片显示域名而不是简介 | `description` 没写 |
| 英文页出现中文 | 文案写进了 `SITE.contact` 而不是 `i18n` |

## 七、我（AI 助手）能做与不能做

这台手机上跑的命令行环境有**明确的能力边界**，说清楚可以省掉来回：

| 能做 | 不能做 |
|---|---|
| 读写工作区里的文本文件 | ❌ 跑构建（没有可用的 node 运行时） |
| 用 git 工具提交、推送、拉取 | ❌ 搬运二进制文件（读进来就损坏，图片必须走网页上传） |
| 抓取 https 页面用于核对（线上 CSS、DOM、图标是否存在） | ❌ 打开浏览器预览、也无法真的渲染 PDF |
| 读你链接的文件夹（受限的那个） | ❌ 读 `Android/data/` 下的其他应用目录（系统限制） |

**推论：凡是我改了样式或组件，都只能「代码审查级」地保证，最终要你刷新确认。**
所以我会把「需要你验证什么」写清楚，你只需要回一句「对了」或「哪里不对」。

同样出于这个原因：**改了样式/组件时，别只看一眼就说好了**，最好把现象反馈给我
（比如「公式还是溢出」「按钮偏上」），我才有依据定位。这也是前面几轮反复的教训。
